# Agent Note: 将所选发布批次提交为一条会话请求

Status: implemented

[English](2026-09-05-backlinks-batch-selection.md) | 中文

## 问题

操作者需要选择多个发布批次，避免反复创建会话。启动连接后轮询全局选中的会话，可能将发布命令发送到之前选中的对话。

## 决策

发布控制台将所选批次号去重、降序排列，作为一条用户请求提交。存储串行处理提交，等待工作区连接返回会话标识后再发送。发布技能仍负责执行；浏览器只负责选择和请求准入。[控制台 README](../../../../packages/client/ui-backlinks-console/README.zh.md) 定义选择与失败行为。

## 考虑过的替代方案

**每个所选批次创建一个会话。** 工作流可能共享浏览器状态，多个会话会产生相互竞争的执行上下文。一条有序请求让发布技能统一协调所选批次。

**启动导航后轮询当前会话。** 选中状态不能证明连接已经完成。等待工作区操作能够取得确切的接收目标，并传播连接失败。

## 影响

准入失败后保留选择，重复点击不会并发提交请求。准入成功不证明发布已完成，也不会在用户指令之外强制执行顺序。现有的 [backlinks 能力决策](../architecture/2026-08-25-backlinks-capability-seam.zh.md) 继续负责提供方和租约语义。

## 验证

存储与组件测试覆盖数字排序、筛选和刷新时的选择、一条请求的准入、连接与发送失败，以及重复点击拦截。Web 场景通过真实 Loader 组合启动，使用本地 HTTP 批次数据和不执行操作的外部模型适配器，检查渲染颜色与选择快照，并观察确切的持久化用户消息。该场景不执行外部发布。
