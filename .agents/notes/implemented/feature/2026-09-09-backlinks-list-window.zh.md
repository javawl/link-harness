# Agent Note: 限制发布列表渲染与刷新工作量

Status: implemented

[English](2026-09-09-backlinks-list-window.md) | 中文

## 问题

每个批次行都会订阅控制台状态。渲染全部历史会增加刷新和面板重新挂载的工作量，重复读取也会拖慢返回刚打开的列表。上游批次 API 不支持分页。

## 决策

客户端保留已获取的概要，初始渲染 50 个匹配结果，每次点击「加载更多」增加 50 个。先筛选再截取，确保旧批次仍可搜索。「全选当前列表」仅接收已渲染的批次号；已选批次独立于显示范围。[批次选择决策](2026-09-05-backlinks-batch-selection.zh.md) 继续负责提交与接收会话的定位。

存储合并进行中的刷新，并在调用方指定的最大时效内复用成功结果。面板以 30 秒轮询间隔作为该时效，跳过后台标签页的轮询，返回可见状态时检查数据时效。手动刷新强制读取；失败保留旧数据并允许重试。

## 考虑过的替代方案

**仅截取服务端响应。** 提供方仍需下载上游完整列表，搜索旧批次还需要另行设计 API。端到端分页需要上游支持。

**将全部行虚拟化。** 显式分页能限制初始渲染，无需引入滚动位置与焦点管理，也为「全选当前列表」提供明确、可验证的集合。

## 影响

初始渲染受到限制，但响应大小和首次上游读取的耗时不变。操作者仍可逐次展开全部历史。重新打开面板会重置显示范围，已选批次继续保留。[控制台 README](../../../../packages/client/ui-backlinks-console/README.zh.md) 定义用户行为。

## 验证

组件检查覆盖分页边界、跨页搜索与选择、刷新合并、时效到期、强制重试、可见状态变化和清理。真实 Web 场景覆盖 50／100／125 行、复用缓存返回面板，以及桌面和窄屏控件，不执行外部发布。
