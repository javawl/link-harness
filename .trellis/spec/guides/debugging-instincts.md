# 调试直觉

这些是跨项目可复用的触发/行动模式。具体事故路径和验证命令应写入当前仓库的项目 Spec。

## 生成产物失败或漂移

**触发：** 安装命令、生成 Agent、运行副本或镜像与预期不一致。

**行动：** 先找到编写来源和生成链路，复现差异，修复来源，重新生成并比较。只有该文件本身就是所有者维护的来源时，才直接修改生成结果。

## 外部路径或接口突然失效

**触发：** 以前有效的 registry、模板、文档或 API 路径返回 404/不支持。

**行动：** 检查上游当前结构、版本和变更记录，不猜路径或所有者。上游布局不稳定时使用已验证、可追踪的版本来源，并同步所有拥有该引用的索引。

## 安装或更新找不到来源

**触发：** 已安装项目无法更新、错误使用业务仓库 remote，或因可选目录缺失而失败。

**行动：** 检查安装时是否保存更新工具、来源元数据和安装模式；按实际模式验证前置条件，不假设所有安装都具有同一目录形状。

## 第三方集成很慢但最终成功

**触发：** 启动过程中重复出现不支持接口和 retry 延迟，最终仍能工作。

**行动：** 定位失败请求和最小兼容边界，测量修改前后结果，保持其他模式不变。依赖升级后重新验证任何本机兼容补丁。

## 多个资产对当前状态说法不一致

**触发：** 摘要、checkpoint、生成文件、状态索引和源码契约给出不同答案。

**行动：** 先明确问题类型，再找到该问题的权威所有者。快照只作历史证据，缓存可以刷新；从来源修复下游视图，不能折中拼接冲突答案。

## 性能结果看起来更好但证据不足

**触发：** 结论来自单次运行、dry run、warmup、环境变化、覆盖缺失或只验证正确性的测试。

**行动：** 停止性能结论，验证原始记录和环境兼容性。证据不足时返回 `invalid`，不能声明改进。

## Git 工作与现有修改重叠

**触发：** 脏工作区中需要暂存/提交、规划后 HEAD 移动，或目标经符号链接解析到其他位置。

**行动：** 记录基线，只采用明确授权文件，验证目标路径和 HEAD。重叠、忽略文件、符号链接、Hook 失败或父提交漂移时失败关闭；禁止使用宽泛暂存掩盖问题。
