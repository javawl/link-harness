# 工程规则

## 先确定资产权威性

每个持久化资产应明确属于以下角色之一：

- **权威来源**：回答某类问题的最终依据，只由明确所有者修改。
- **快照**：保留某个时间点的恢复或交接视图，不覆盖当前事实。
- **缓存**：从其他资产派生，可以重新生成，不能高于来源。

权威性必须按问题划分。产品契约、技术设计、执行计划、运行状态和历史记录回答的问题不同，不能合并成一条全局优先级。

## 修改来源后再生成

- 修改安装产物、生成文件、vendor 副本或运行时镜像前，先找到真正的编写来源。
- 修改来源并运行仓库现有生成器，再验证下游副本一致。
- 只有在同步检查、来源缺失或验证安装结果时，才把生成副本作为主要读取对象。
- 运行时读取某个生成文件，并不意味着该文件可以被手工修改。

## 稳定规范与实时状态分离

- 顶层 Agent 指南只保存长期规则和导航，不写当前任务、临时结论或原始遥测。
- 生命周期状态、机器记录、人类交接和跨任务契约应放在各自拥有的文件中。
- 来源变化后刷新摘要或缓存，不能把过期派生视图当作当前事实。

## 按文件格式选择工具

- 读取前先识别文本、图片、归档、PDF、媒体或其他二进制格式。
- 使用对应解析器或查看器，不把二进制内容或大段 base64 注入文本上下文。
- 能用路径、元数据或提取文本表达时，不复制完整原始内容。

## 从重复证据升级护栏

使用足以防止已观察失败的最低强度机制：

1. 低频且依赖判断的问题写文档。
2. 结构稳定但仍需解释的问题使用模板或上下文注入。
3. 高频、局部、可廉价检测的问题使用 Hook 或检查器。
4. 字段和不变量稳定后使用 Schema 或 Lint。
5. 只有检测确定且误报成本可接受时才升级为 CI 阻断。

单次事故或单次需求结论不能直接成为全局阻断规则。提升前必须证明问题可重复、影响范围稳定且检测方式可靠。

## 保持范围和恢复边界

- 修改必须停留在用户授权的所有权范围内。
- 破坏性迁移或大范围重新生成前记录可恢复基线。
- 回滚和迁移恢复是设计的一部分，不是失败后的临时清理。
- 脏工作区中只采用明确授权的文件，禁止扩大暂存范围来让提交成功。
