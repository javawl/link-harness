# 证据标准

## 正确性与性能是不同结论

- 测试通过、生成同步和安装成功只能证明覆盖范围内的正确性。
- 它们不能证明延迟、Token 或工具调用减少。
- 性能结论必须有环境和输入可比的 baseline/candidate 样本。
- 性能变快但正确性或就绪门禁变弱，结果仍然失败。

## 比较必须可复现

- 固定 revision，并保持环境、模型、权限、输入和网络模式兼容。
- 明确 warmup 与正式测量，不能把两者混合。
- 多次样本应交错执行，降低时间顺序偏差。
- 网络测试、镜像检查和默认路径结果分开记录。
- 报告必须同时保留正确性门禁和性能样本资格。

具体项目需要在项目 Spec 中定义最小样本数、统计方法和可执行命令；通用 Guide 不虚构统一阈值。

## 未观测值不是零

- 未采集的数据使用 `null` 或明确的 unavailable 状态。
- 零是实际测量值，不能用来伪装缺失数据。
- 数据值与覆盖状态冲突时，验证必须失败关闭。

## 原始事实与导航分离

- 机器事实写入可追加的报告或 ledger。
- 状态文件保持小型，只提供当前状态和导航。
- Journal 或 checkpoint 用于人类交接与恢复。
- 派生摘要必须能够从原始事实重建，不能成为第二个权威来源。

## 机器证据失败关闭

- 写入前验证必填字段、枚举和 Schema。
- 使用稳定序列化和去重身份，避免重试或并发产生静默重复。
- 修正不可变测量记录时创建新的替代记录，不覆盖历史。
- 中断、无效、warmup、环境不兼容或 revision 不匹配的样本不得进入正式比较。

## 遥测保持低敏感度

- 只记录必要标量、标准枚举、仓库相对路径、不可逆身份摘要和 revision。
- 禁止记录 prompt、diff、secret、环境变量值、用户绝对路径和临时目录。
- 新遥测字段在写入前必须完成 Schema 和隐私边界评审。

## 报告门禁而不只报告数字

比较报告至少说明：证据资格与覆盖、正确性结果、缺失/不兼容样本、revision/环境组合，以及带原因的 `pass`、`fail` 或 `invalid` 结论。
